# v235 — Full-resolution front-to-back opaque render scheduling

## Evidence / problem
v234 Quest 3S O2 Megaton median stereo GPU 25.59 ms versus 13.89 ms for 72Hz. Temporary 70%-dimension rendering was dramatically faster; bypassing world material shading at full resolution less so. These were different views and cannot quantify individual bottlenecks. In source, Q2017RenderOpaqueDetailedInstanced issued opaque singles, fallbacks and instanced groups ordered chiefly by mesh/material key, rather than front-to-back. Nearby architecture and distant surfaces could therefore write/shade the same pixels more than necessary.

## Shipped change
Q235 builds one draw packet per existing detailed opaque draw, preserving every source object, material, shader, texture, UV, geometry buffer, instance transform and draw count. It reuses the existing published visibility sets and stereo instance matrix buffer. Each regular depth-writing opaque packet receives the nearest point of its transformed AABB to the first-eye position and a 4m distance bucket. Within each bucket, shared-material keys retain coherence. The schedule is computed once per stereo frame and shared by both eyes, not sorted per eye.

Only contiguous runs with depth testing and depth writes enabled, no decal and no no-lighting falloff may be reordered. All other draws are fixed barriers (position and relative order preserved), and ALL alpha, additive environment, player/NPC, terrain, sky, water, and reflection draw paths are untouched. The reflection camera keeps the old exact packet order. This creates no added depth prepass, GPU sync, resolution reduction, LOD fade change or visual downgrade. Depth order can help hardware early-depth rejection but GPU gain is UNMEASURED until headset test.

## Toggle and validation
Production Q235 is enabled by default. v235 O2/debug can disable ONLY this feature for a controlled, matched-viewpoint A/B by setting `debug.falloutquest.opaque_front_to_back 0`, force-stopping and reopening the game. To reenable set value to 1 and reopen. Keep `debug.falloutquest.fast_material 0`, `debug.falloutquest.render_scale 0`. The `Q235 OPAQUE EARLYZ` log records eligible, moved and barrier packet counts and exact state. Compare matched views inside and outside Megaton after streaming completes. Check real FPS, per-eye and stereo GPU time, p90/p99, frame cadence, draw calls, vertices, state changes and CPU prep cost. Confirm same visibility, decals, coplanar metalwork and alpha-tested foliage in both eyes. Check that mirror, refraction, bloom, MSAA=2x, HDR and compositor depth work.

This is the first stage of a larger tile-friendly renderer effort, not a completed framebuffer architecture overhaul. If negligible, the next large target is native indexed NIF geometry (especially Wasteland vertices) and reduction of water/HDR intermediate framebuffer traffic without sacrificing fidelity.
