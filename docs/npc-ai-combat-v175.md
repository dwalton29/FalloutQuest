# Authored resident Flee From — version 175

Version `0.46.3-authored-flee`, extending main `2c39e350d9d1dd3f031bcd9eeded5b1662ddd910`. This increment retains the combat, door, Escort, Patrol, dialogue, weapon and save behavior documented in versions 172–174. It does not complete the full AI/combat milestone.

## Source data and supported behavior

The Fallout 3 [xEdit definitions](https://github.com/TES5Edit/TES5Edit/blob/dev-4.1.6/Core/wbDefinitionsFO3.pas) identify PACK type 10 as Flee Not Combat and PTDT as a reference with an authored distance. The [GECK Flee package documentation](https://geckwiki.com/index.php?title=Flee_not_Combat_Package) distinguishes Flee From from Flee To and states that package conditions gate entry but do not terminate an already running Flee package. The supplied Fallout3.esm contains eight such packages; four have script-free reference/distance definitions with no start location or procedure actions.

Supported Flee From packages require a specific player or resident living actor reference, a positive PTDT minimum distance, no PLDT start location, and no executable script or nonzero INAM/TNAM procedure action. Package order, schedules, known conditions and template inheritance retain the existing selection owner. False known conditions prevent entry but do not terminate a running Flee phase. Unsupported conditions still reject, including after restore. Schedule expiry and higher-priority supported package selection retain the existing bounded selection policy. Missing/dead/unavailable targets permit lower-priority supported packages rather than using stale spawn coordinates.

Separation uses the existing planar game-coordinate navigation bridge; full three-dimensional detection and escape-distance parity remain unfinished. Within the resident NAVM graph, the actor chooses a nearby reachable triangle centroid meeting its authored separation; if none meets it, it chooses the farthest reachable centroid that improves separation. This endpoint policy is a bounded adaptation, not Bethesda path/escape choice parity. Only existing reciprocal authored portals are traversed. The shared search now also owns combat's existing farthest-centroid routing without changing its distance policy. Every movement step retains authored surface grounding and the version-174 local-door/collision bridge. Planning is bounded to destination exhaustion or a moving threat, with at least 0.75 seconds between attempts; no ESM scans, asset loading or NAVM rebuilding occurs while executing it. Once minimum separation is reached, the actor pauses and resumes avoidance if the threat closes again. No combat hostility is manufactured by this package, and legitimate combat supersedes it.

The current prepared Walk/Turn/Idle clips and 1.05 m/s VR locomotion bridge remain in use. Running, cowering and complete Flee animation/procedure parity are not claimed. Flee To and Flee From with a start location remain rejected because their full arrival/cower and procedure behavior is unfinished. Object threats, load-door escape, nonresident continuation and advanced cover remain unsupported.

## Follow targets and persistence

Follow and Flee share a resident actor-root resolver. A moving loaded NPC uses its current simulation root, not its last persisted or authored spawn point. Before that resident actor's first restoration, the resolver uses its validated canonical saved position. Canonical world/interior-cell identity, actor health, lifecycle and required resident rig are checked. Self, dead, unconscious, unavailable and nonfinite targets reject. Player references use the existing VR head-to-game-coordinate bridge. This does not complete Follow start/end location, PKFD trigger or combat directive semantics.

A Flee sequence of one records that its entry condition has already passed. Existing save revision 9 retains that phase across save/load, streaming suspension and combat interruption, rebuilding a NAVM route from the canonical restored transform. No transient route, pointer or monotonic timestamp is serialized. Previous save revisions remain readable without a new format. Nonresident actors remain frozen.
