# NPC local doors and player Escort — version 174

Version `0.46.2-npc-doors-escort`, extending main `9f82ebd31693aed4da7386fcb115a89404ea568c`. This continues the resident actor milestone documented in [version 172](npc-ai-combat-v172.md) and [Patrol version 173](npc-ai-combat-v173.md); the complete requested AI/combat acceptance criteria are still unfinished.

## Local door navigation

Resident humanoid package and combat movement now identifies an ordinary local door when the existing world collision blocks its next NAVM movement segment. A bounded query of cached resident door geometry must identify a local swing door within the remaining route segment, with no other world obstruction before it. Unresolved obstruction queries are bounded to 2 Hz and reuse the existing door ray/bounds helper and VR activation reach. They never invoke the player query’s authored-load-door fallback or scan ESM. A cached pending door reference avoids scanning rendered objects each waiting frame. Replanning discards that transient reference.

NPC access uses immutable authored reference validity/flags, lock/key data and the actor's canonical inventory. Player keys cannot authorize an NPC. Scripted doors reject NPC activation, including scripts previously verified only for player default activation. Unlocked ownership does not itself prevent physical opening, consistent with the existing player policy; trespass/crime behavior is not implemented.

The NPC requests opening once through the existing local-door animation/collision runtime, with the actor as activator for the existing hinge fallback. It never toggles an opening/open door closed or reverses a closing animation. Movement waits for the original NIF sequence to finish (or the existing rigid-door fallback to settle), then rechecks world collision. A scene-serial cache of original local-door bounds also blocks movement through another activator’s opening/closing door while the existing runtime temporarily disables its collision. That conservative barrier remains valid after replanning; it rebuilds once per scene when first needed, not per actor/frame. The existing authored door audio dispatch is used. The final short waypoint step checks collision too, preventing its prior unconditional snap through a closed door.

There is no new renderer, animation parser, collision store or parallel door state. Player activation, its Open/Close prompt, audio and XTEL loading transition retain their existing ownership and policy. No NPC code calls the player transition queue or resets the VR origin.

Limitations: NPC opening is bounded by the existing resident interior local-door support. Load doors, NAVM door-link metadata, independent actor cell transfer, off-screen door interaction and automatic close/lock/unlock package directives remain unfinished. Nonresident actors retain the existing frozen canonical state. Door state retains the existing door runtime's persistence behavior; this change does not introduce saved door lock/open states. Movement remains the existing chest-ray/NAVM grounding bridge, not a complete actor capsule/crowd sweep. Unavailable or unsupported doors block and diagnose, rather than granting traversal.

## Script-free player Escort

FO3 xEdit defines PACK type 2 as Escort and PKE2 as an unsigned authored escort distance. The original supplied ESM contains 30 Escort packages; representative original `000C2F11` has a player PTDT reference and PKE2 distance 300. Its scripts are empty. Layouts and behavior were cross-checked against [xEdit FO3 definitions](https://github.com/TES5Edit/TES5Edit/blob/dev-4.1.6/Core/wbDefinitionsFO3.pas) and the [GECK Escort documentation](https://geckwiki.com/index.php/Escort_Package).

Supported packages require a specific player reference target, explicit PKE2, and a supported fixed reference/editor PLDT destination in the resident scene. The NPC approaches an out-of-range player first, then leads along authored NAVM to the destination. It pauses when the player falls beyond the authored distance, and continues when the player is closer to the destination. Arrival holds the destination while that package remains selected. Existing PKID priority, schedule/conditions and script rejection remain in force. No name/EDID-specific behavior exists.

The existing saved sequence field now retains Escort procedure phase (approach, lead, arrived) across save/stream restore and combat interruption. Paths rebuild from the canonical current actor transform. FQPS revision 9 extends each actor record by one finite nonnegative remaining package-wait duration; revisions 1–8 remain readable, with prior saves defaulting that duration to zero. No transient clock timestamp, door reference, animation state or path pointer is written to saves. Patrol marker waits now preserve their remaining duration across save/unload restoration and suspend it during combat, then resume it with the retained leg. The paused nonresident/combat countdown is an explicit bounded-runtime policy, not a claim of full Bethesda off-screen timing parity.

This is the player-escort subset: NPC targets require a temporary forced-Follow owner, and object targets require canonical pickup/drop/search behavior; those targets explicitly reject instead of pretending to escort. Escort radius is evaluated in the existing planar game-coordinate navigation bridge. Full package procedure/result-script/completion flags, NPC/object escort, actual door-linked routes and nonresident continuation remain unfinished. Eat, Sleep and authored Flee remain unsupported.

They cover actor-owned versus player-owned keys, scripted-door rejection, walls before doors, opening/closing waits, no repeated toggle/audio, load-door isolation, and short-waypoint collision. Escort tests cover approach, authored-distance pause, a player ahead, destination arrival, unsupported targets, and retaining phase through combat/save restoration. Save tests cover wait round-trips, v6/v7/v8 migration and valid-CRC NaN-duration corruption rejection.

Optional original ESM tests verify real NPC key/door access, the authored player Escort record, existing 28 actor-linked Patrol routes, representative weapons/NPCs and Lucas greeting. Existing original combat/death KF tests remain applicable; no original Bethesda data is committed or packaged.

All relevant host suites and the Android workflow must pass for the delivered HEAD. Headset validation remains required for NPC local-door approach/animation/collision timing, route blockage/replanning, Escort pacing and dialogue/combat interruption, and unchanged player doors, physical weapons, corpse loot and save restoration. Full load-door traversal, additional package families, fuller detection/damage/animation parity, essential unconscious recovery and creatures remain follow-ups.
