# Graphics-session resource lifetime — v272

The supplied v271 headset log identifies source `27c4bdd`, O2 profile, and `requested=vulkan selected=vulkan`. It contains only the SpaceWarp capability request, no motion producer creation or synthesis attachment. That producer is GLES-only. The prior GLES repair could not affect this Vulkan session.

The same log reports native draw rejection (`skipProgram=9 skipMesh=71` in late frames), despite live terrain, LOD and player submissions. The sky's first rejected program is `9091`, while the newly created main world program is `19333`; CPU handles already start above 19000 at the new renderer's first frame. These are consistent with graphics owners retained across an immersive activity relaunch in the same Android process.

Source inspection confirms the missing lifetime boundary. Vulkan destroys its resource registry on renderer shutdown. Existing scene teardown clears the main world, but not the player body, sky programs/geometry/clouds/sun, LOD blocks or terrain texture caches. Their ready/cache flags permit reuse without registering/uploading into the replacement backend. Missing image handles silently resolve to white Vulkan fallback images; missing program/mesh handles reject draws. GLES context replacement has the same ownership problem.

Scene GPU teardown is now explicit and runs before destruction of either backend, independently of wrapper framebuffer allocation. It stops/drains resident work, releases the player and skin resources, marks body construction retryable, clears all LOD geometry/origin readiness, releases terrain geometry and its diffuse/normal GPU caches, releases both sky owners, and clears world/cube images and GPU-known texture keys. Shared geometry is cleared after its owning objects. Ordinary cell transitions continue to retain terrain texture caches; only session end expires them. CPU game data remains available for reconstruction.

The new regression compiles the actual sky/terrain owner teardown functions against tracked resource deletion and runs three create/release/release cycles. Source integration guards verify owner-before-shared-cache and owner-before-backend ordering, including initialization failure before framebuffer allocation. Existing render/loading/actor integration checks remain required. Headset relaunch verification is still needed; the log and code establish the failure mechanism, not a verified visual result after this patch.

Vulkan selection remains explicit. A new log states `SPACEWARP inactive backend=Vulkan reason=motion-producer-GLES-only` instead of leaving capability negotiation as the only status. To exercise the implemented all-scene SpaceWarp path, select GLES with `adb shell setprop debug.falloutquest.renderer gles`, force-stop `com.falloutquest.app`, and launch again. This patch does not implement a Vulkan motion producer or silently change the selected backend.
